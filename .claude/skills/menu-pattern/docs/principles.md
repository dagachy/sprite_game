# 메뉴판 / 레시피 원칙

조건부 로드형 스킬 설계의 2단계 비유.

## 비유

| 비유 | 역할 | 특성 |
|---|---|---|
| **메뉴판** | 라우터 SKILL.md | 어떤 요리가 있는지 **목록만** 보여준다. 조리법은 담지 않는다. |
| **레시피** | references/*.md | 특정 요리의 **상세 조리법**. 손님이 주문한 요리만 꺼내온다. |

손님은 메뉴판 전체를 외우지 않고, 주문한 레시피만 받는다. 토큰 비용도 동일하게 동작한다.

## 원칙 4종 (감사기 R1~R4에 매핑)

### R1. 라우터는 짧다 (≤ 30줄)
메뉴판은 요리 N개의 **이름만** 담는다. 조리법이 섞여들면 메뉴판이 아니다.

### R2. 라우터는 조건부 링크로만 구성
"X 관련 요청이면 → references/X.md" 형식만 둔다. 분기 N개 → `.md` 포인터 ≥ N개.

### R3. 라우터에 본문·상세 금지
라우터 안에 코드블록, H3+ heading(세부 소단락)이 등장하면 안 된다. 그런 내용은 레시피 쪽으로 밀어낸다.

### R4. references 간 cross-ref 금지
`finance.md` 가 `inventory.md` 를 참조하면, "매출 주문"에 재고 레시피까지 끌려온다. 조건부 로드의 이점이 소멸하므로 references는 **서로 독립**이어야 한다.

## 확장 규약

새 도메인을 추가하려면 2곳만 바꾼다.

1. 라우터 SKILL.md 에 조건부 링크 **1줄** 추가.
2. `references/<new>.md` **1파일** 신규 생성.

기존 references는 **수정 없음**. 이것이 cross-ref 0이 주는 선물.
