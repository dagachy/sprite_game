# 분리 신호 표

> 하네스 엔지니어링 — 5장: 스킬 분리 판단 기준

스킬 본문을 점검해 아래 3가지 신호 중 하나라도 발현되면 분리를 권고한다.

| 번호 | 신호 이름 | 발현 조건 | 분리 방향 |
|------|----------|-----------|-----------|
| 1 | **크기 신호** | 본문 500줄 이상 (`wc -l`) | 역할·단계 기준으로 2개 이상 스킬 분리 |
| 2 | **도메인 분기 신호** | 도메인 분기 키워드 2개 이상 ("~이면 A, ~이면 B" 패턴) | 도메인별 전문 스킬로 분리 |
| 3 | **조건부 상세 신호** | "~이면 → 참조" 패턴 1개 이상 | 조건부 위임 스킬 생성 또는 기존 스킬 참조로 대체 |

---

## 신호별 상세 설명

### 1. 크기 신호

**정의:** 스킬 본문 자체가 지나치게 길어진 상태.
**원인:** 단일 스킬에 여러 단계·책임이 쌓인 경우.
**탐지:** `wc -l SKILL.md` → 500 이상이면 발현.
**예시:** 빌드·테스트·패키징·배포·롤백을 한 스킬에 모두 기술.
**분리 기준:** Phase나 독립된 역할 단위로 2개 이상 스킬로 나눈다.

---

### 2. 도메인 분기 신호

**정의:** 동일 스킬 내에서 업무 도메인에 따라 처리 흐름이 달라지는 상태.
**원인:** "매출팀이면 A를, 재고팀이면 B를" 같은 분기가 본문에 직접 기술된 경우.
**탐지:** `grep`으로 도메인 분기 키워드 2개 이상 탐지.
**예시:** 매출 KPI, 재고 KPI, 인사 KPI를 하나의 스킬에서 분기 처리.
**분리 기준:** 도메인별 전문 스킬로 분리하고 라우터 스킬을 둔다.

---

### 3. 조건부 상세 신호

**정의:** 특정 조건일 때만 활성화되는 절차가 타 스킬 위임으로 처리된 상태.
**원인:** 조건부 흐름을 스킬 내부 분기가 아닌 타 스킬 포인터로 해결한 경우.
**탐지:** `grep`으로 "~이면 → 참조" 패턴 1개 이상 탐지.
**예시:** "대용량이면 → batch-exporter 스킬 참조"처럼 위임 패턴이 본문에 존재.
**분리 기준:** 조건 분기 자체를 라우터 또는 조건부 스킬로 추출한다.

---

## 진단 우선순위

신호가 복수 발현될 경우 아래 순서로 처리한다.

1. 크기 신호 → 먼저 단계 분리 후 재진단
2. 도메인 분기 신호 → 도메인 전문 스킬 분리
3. 조건부 상세 신호 → 위임 스킬 정리

크기와 도메인이 동시에 발현되면 도메인 분리를 우선한다 (분리 후 크기 신호 자연 해소되는 경우 많음).
