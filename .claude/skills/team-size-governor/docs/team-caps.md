# 팀 규모 상한 (ex-06-15 + ex-12-03 원칙)

## 왜 상한을 두는가

**ex-06-15 "292 agent incident"**: 조율 채널 N(N-1)/2 증가로 통신·동기화 비용 폭발. 15명 넘기면 사실상 조율 불가.

경험칙:
- 전체 팀: **5명 이하** 권장 (상한 7명, 그 이상은 경고).
- Phase별 동시 활성: **3~5명**.

## 두 가지 측정 축

| 축 | 설명 | 모드 |
|-----|------|------|
| 전체 수 | 하네스에 등록된 모든 에이전트 수 | directory |
| Phase별 활성 | 특정 Phase에서 동시 실행되는 수 | matrix |

**전체 8명이어도 Phase당 3명씩 활성화**하면 조율 복잡도는 3명 팀 수준. ex-12-03의 핵심.

## 상한 조정

프로젝트별 특성에 따라 `MAX_TEAM_SIZE` / `MAX_CONCURRENT` 환경변수로 override.
단, 상한을 올리는 것보다 **역할 통합/Phase 분할** 을 먼저 고려할 것.

## 범위 밖

- 각 에이전트가 실제로 활성화되는 시점/빈도 (런타임 측정 필요).
- 에이전트 간 통신 그래프 복잡도.
