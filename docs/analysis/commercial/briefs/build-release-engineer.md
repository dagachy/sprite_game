# 실무 전달 브리핑: 빌드·릴리스 엔지니어용 (탕탕특공대 / 탕탕에이스 분석)

- 대상: `build-release-engineer`
- 근거 문서: `docs/analysis/commercial/tangtang_analysis.md` (§2.1, §2.7, §4 #10, §5)
- 원칙: 원작의 빌드, 패키지, 운영 일정을 추정해 적용하지 않는다. 출시 운영 원리만 참고한다.

## 1. 한 줄 요약
릴리스 관점의 교훈은 두 가지다. **출시 직후 기간 한정 이벤트를 운영할 수 있는 원격 설정 구조**가 필요하고, **시즌 콘텐츠를 앱 업데이트 없이 교체할 수 있는 구조**가 필요하다. 빌드 파이프라인은 이 두 가지를 전제로 설계한다.

## 2. 구현해야 할 것 (우선순위순)

### [상] 빌드 자동화 기초
- Unity 배치 모드 빌드 스크립트를 만든다. 안드로이드 AAB, iOS Xcode 프로젝트를 같은 스크립트에서 낸다.
- 빌드 번호는 CI 실행 번호로 자동 증가시킨다. 버전 표기(사용자용)와 빌드 번호(내부용)를 분리한다.
- 키스토어와 서명 인증서는 저장소에 넣지 않는다. 비밀 값 취급은 사용자 승인 대상이다(프로젝트 지침).

### [상] 원격 설정 릴리스 경로
- 앱 업데이트 없이 시즌 이벤트와 일일 변형 규칙을 바꿀 수 있어야 한다. backend-engineer가 만든 원격 설정 채널과 연결한다.
- 설정 변경은 단계적 배포(일부 사용자 먼저)를 지원하게 한다.
- 분석의 교훈: 출시 초기 7일 무료 지급과 기간 이벤트(분석 §2.7)는 날짜에 맞춰 정확히 열리고 닫혀야 한다. 시간대 기준(서버 UTC 또는 현지 시각)을 한 곳에 정의한다.

### [중] 시즌·이벤트 일정 검증
- 이벤트 기간이 겹치거나 빈 날이 생기면 빌드 전에 경고하는 검증 스크립트를 만든다.
- 이벤트 종료 후에도 이벤트 전용 보상이 남지 않는지 확인하는 항목을 포함한다.

### [중] 스토어 제출 체크리스트 연결
- 제출 전 점검을 store-compliance-specialist와 함께 정한다. 연령 등급, 개인정보 처리방침, 데이터 안전성 양식, 확률 공개 표기가 포함돼야 한다.
- 탕탕특공대는 확률 공개 표기를 하고 있다(나무위키 기재). 우리 게임이 뽑기를 넣으면 같은 수준의 공개를 기본으로 한다.

### [하] 출시 후 긴급 패치 경로
- 치명적 버그 시 원격 설정으로 기능을 끄는 킬 스위치를 둔다. 판 시작 기능, 결제 기능, 방치 수익을 각각 끌 수 있게 한다.

## 3. 하지 말 것
- 원작의 패키지 이름, 아이콘, 스토어 설명 문구를 옮기지 않는다.
- 출시 날짜를 분석 문서의 날짜(탕탕에이스 헤더 2026-10-23)에 맞추지 않는다. 기사별 표기가 엇갈린다는 것이 확인됐다(미확인).

## 4. 열린 질문
- 출시 플랫폼 우선순위(안드로이드 먼저인지 iOS 동시인지).
- 테스트 트랙을 내부 테스트부터 몇 단계로 할지.
- 스토어 업로드는 사용자 승인 대상이다. 업로드 자동화를 만들더라도 실행은 승인 후에만 한다.

## 5. 완료 기준
- 배치 모드 한 번으로 AAB와 iOS 프로젝트가 나온다.
- 원격 설정 변경 후 앱 재배포 없이 이벤트가 열리고 닫힌다.
- 이벤트 일정 검증 스크립트가 겹침과 공백을 잡아낸다.
