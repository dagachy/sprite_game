# 실무 전달 브리핑: 게임플레이 프로그래머용 (탕탕특공대 / 탕탕에이스 분석)

- 대상: `gameplay-programmer`
- 근거 문서: `docs/analysis/commercial/tangtang_analysis.md` (§2, §3, §4, §6)
- 원칙: 공개 정보와 플레이 관찰만 사용. 원작의 코드, 수치, 에셋, UI는 재현하지 않는다. 아래는 "무엇을 구현할지"의 방향이다.

## 1. 한 줄 요약
탕탕에이스 계열의 **한 손 드래그 이동 + 손을 떼면 감속 + 판마다 다른 3택 빌드**가 핵심이다. 조작은 단순하게, 생존 판단은 위치 선택에서 나오게 만든다.

## 2. 구현해야 할 것 (우선순위순)

### [상] 입력과 이동
- 세로 화면 한 손 드래그 이동. 드래그 델타를 목표 위치 또는 속도로 바꾸고, Rigidbody2D 또는 커스텀 이동 중 하나를 고른다. 터치 입력은 New Input System을 쓴다.
- **손을 떼면 감속(시간 배율 또는 이동·전투 속도 감소).** 감속 값은 `ScriptableObject` 튜닝 값으로 뺀다. 이 기능은 설계 검증의 핵심이므로 on/off 토글을 둔다.
- 자동 발사, 자동 조준. 플레이어가 직접 조준하지 않는다.

### [상] 한 판의 구조
- 5~10분 한 판. 웨이브 → 정예 → 보스 순서. 보스 처치 시 클리어, 기체 파괴 시 종료. 종료 조건을 코드에서 한곳에 모은다.
- 보스 등장 시 일반 적 정리 같은 연출성 규칙은 "필드 정리 이벤트"로 한 번에 처리한다(원작 관찰: 보스 등장 시 필드 몹 소멸).

### [상] 레벨업 3택 빌드
- 레벨업마다 무작위 3개를 제시한다. 선택지 종류는 (a) 신규 무기 추가, (b) 주력 무기 강화 집중, (c) 패시브 등으로 나눈다.
- 무기 강화는 3레벨마다 핵심 강화가 붙는 구조를 권장한다(에이스 관찰). 레벨 값은 데이터로 뺀다.
- 적 원소 약점 표시와 연결되도록 원소 속성을 무기와 적에 함께 붙여 둔다.

### [상] 공격 모양의 단계 변화
- 강화 단계마다 공격의 모양(갈래 수, 타격 형태)이 눈에 띄게 바뀌게 한다. 프리팹을 단계별로 나누는 방식이 간단하다. 실제 모양 디자인은 technical-artist와 협의한다.

### [중] 적 설계 로직
- 추격형, 고체력, 부술 수 있는 탄(적 미사일) 세 종류부터 시작한다. 추격형은 이동 부담, 고체력은 시간 부담을 주는 역할이다.
- 적 AI는 상태 머신으로 구현한다(추격, 정지 사격, 돌진 등).

### [중] 판 밖 성장 연결점
- 판에서 나온 재화는 판 밖 성장축의 입력이 된다. 이 인터페이스(판 결과 구조체)만 정의하고, 판 밖 로직은 ui-implementer나 backend-engineer와 나눈다.

## 3. 구현하지 않을 것 (분석에서 나온 반면교사)
- 에너지 소모 차단형 진입 구조는 게임플레이 코드에서 다루지 않는다. 이는 기획 결정이다.
- 탄막이 늘수록 가독성이 무너진다. 탄 종류를 무한정 추가하지 않는다. 종류 상한을 먼저 정한다(추정 상한: 초기 4~6종).

## 4. 검증 방법 (분석 §6 연계)
1. **감속 프로토타입 A/B:** 감속 on/off 두 빌드로 5명 이상 테스트. 클리어율과 이탈 시점을 기록한다. 데이터는 `_workspace/qa_perf/`에 둔다.
2. **3택 풀 12종:** 무기 4종 × 강화 3단계로 같은 시드에서 판마다 빌드가 갈라지는지 확인한다.
3. **5분 한 판:** 웨이브 3, 정예 1, 보스 1 구조로 빌드하고 재도전 의사를 확인한다.

## 5. 열린 질문 (기획 확인 필요)
- 감속은 이동 속도만 줄이는가, 전투 속도(발사 간격)까지 줄이는가. 분석은 "전투 속도"로 표현했으나 원작 확인은 안 됐다.
- 판의 길이는 고정인가, 보스 전투 중에 늘어나는가.
- 원소 약점 표시를 얼마나 노출할지. 노출이 많으면 빌드 선택이 쉬워지고, 적으면 무작위의 긴장이 커진다.

## 6. 완료 기준
- 감속 on/off 토글로 같은 씬에서 비교 가능.
- 3택이 데이터 파일(ScriptableObject)만 바꿔도 풀이 교체됨.
- 보스 등장 시 필드 정리와 클리어·종료 조건이 단위 테스트 또는 플레이 로그로 확인됨.
