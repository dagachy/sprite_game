# 실무 전달 브리핑: 레벨 파이프라인 엔지니어용 (탕탕특공대 / 탕탕에이스 분석)

- 대상: `level-pipeline-engineer`
- 근거 문서: `docs/analysis/commercial/tangtang_analysis.md` (§2.2, §2.5, §4, §5)
- 원칙: 원작 맵 데이터, 에셋, 웨이브 수치를 추출하거나 재현하지 않는다. 구조 원리만 반영한다.
- 주의: Sprite Fusion 출력 임포터는 실제 샘플 맵 없이 만들지 않는다(프로젝트 지침). 샘플 맵이 확보되기 전에는 설계와 인터페이스 정의까지만 한다.

## 1. 한 줄 요약
이 게임의 "레벨"은 타일맵보다 **웨이브 스크립트**에 가깝다. 한 판은 5~10분의 **웨이브 3개 + 정예 1 + 보스 1** 구조다. 파이프라인은 타일맵 임포트와 별도로 **웨이브 데이터 포맷**을 설계해야 한다.

## 2. 구현해야 할 것 (우선순위순)

### [상] 웨이브 데이터 포맷
- 한 스테이지를 `ScriptableObject` 또는 JSON으로 정의한다. 필드 예: 웨이브 번호, 시간 또는 조건, 스폰 목록(적 종류, 수, 간격, 위치 규칙), 보상 테이블 참조.
- 웨이브 종류를 최소 3개로 나눈다: 일반, 정예, 보스. 보스 웨이브 시작 시 필드 정리 이벤트를 발생시키는 플래그를 둔다(원작 관찰 기반).
- 스테이지 길이는 데이터로 계산 가능해야 한다. 목표값(5~10분)을 검증하는 에디터 도구를 만든다.

### [상] 스테이지 검증 에디터 도구
- 검증 항목: 웨이브 누락, 보스 웨이브가 마지막에 있는지, 판 길이 추정치가 5~10분 범위인지, 적 종류가 등록된 프리팹과 일치하는지.
- 결과를 콘솔 경고 목록으로 낸다. 빌드 전 자동 실행이 가능하도록 배치 모드에서도 돌게 한다.

### [상] 타일맵 레이어와 콜라이더
- 전장 타일맵은 장애물과 경계만 담는다. 콜라이더는 Composite Collider 2D로 합쳐 성능을 확보한다.
- 탄 충돌은 레이어를 분리한다(플레이어 탄, 적 탄, 장애물). 부술 수 있는 탄은 장애물과 별도 레이어로 둔다.
- 장애물 배치는 가독성 규칙을 따른다: 장애물 근처에 탄막이 겹치지 않도록 금지 구역을 데이터로 표시한다. 자세한 기준은 level-designer와 협의한다.

### [중] 스테이지 목록과 해금
- 메인 스테이지(일반, 정예, 보스 순)를 목록으로 관리한다. 다음 스테이지 해금 조건을 데이터에 넣는다.
- 상시 던전 해금 조건(예: 메인 특정 스테이지 클리어)을 같은 방식으로 정의한다.

### [중] 일일 변형 규칙 로딩
- 일일 도전은 "강화 1 + 부작용 1" 규칙 쌍을 스테이지 데이터에 덧씌우는 구조로 만든다. 예: 이동 속도 증가 + 적 가속. 규칙은 독립 모듈로 두어 조합이 늘어나도 코드를 바꾸지 않게 한다.

### [중] 로딩과 스트리밍
- 한 판의 스폰 데이터는 판 시작 전에 모두 로드한다. 판 중간 로딩 스파이크를 피한다.
- 메모리 상한이 있는 저사양 기기를 고려해 스테이지별 에셋은 어드레서블이나 로드 해제 정책으로 관리한다(mobile-performance-engineer와 협의).

## 3. 하지 말 것
- 원작 맵의 배치나 스폰 패턴을 옮기지 않는다.
- 판 길이를 맞추려고 스폰을 무작정 늘리지 않는다. 길이는 웨이브 조건으로 조절한다.

## 4. 열린 질문
- 웨이브 종료 조건을 시간으로 할지, 처치 수로 할지. 분석은 시간 기반을 가정했으나 결정이 필요하다.
- 상시 던전(운석 폭격류)을 같은 포맷으로 다룰지, 별도 포맷으로 둘지.
- 샘플 맵 입력이 확보되기 전까지 Sprite Fusion 임포터 작업은 대기한다. spritefusion-expert의 워크플로 확인을 먼저 받는다. Sprite Fusion MCP 호출은 크레딧이 들므로 호출 전 비용을 확인한다.

## 5. 완료 기준
- 웨이브 데이터만 바꿔 판 구성을 바꿀 수 있다(코드 수정 없음).
- 검증 도구가 판 길이 추정치와 보스 배치를 자동으로 검사한다.
- 5~10분 한 판을 가정한 샘플 스테이지 1개가 시뮬레이션 또는 플레이로 확인된다.
