# 실무 전달 브리핑: UI 구현자용 (탕탕특공대 / 탕탕에이스 분석)

- 대상: `ui-implementer`
- 근거 문서: `docs/analysis/commercial/tangtang_analysis.md` (§1.4, §1.7, §2.4, §2.5, §4)
- 원칙: 원작의 화면 배치, 아이콘, 폰트, 색을 옮기지 않는다. 구조와 정보 설계만 참고한다.

## 1. 한 줄 요약
판 안에서는 **3택 선택 UI와 최소한의 HUD**가 전부다. 판 밖에서는 **성장축 여러 개를 해금 순서대로 안내하는 구조**가 핵심이다. 정보 밀도보다 "지금 무엇을 하면 되는지"가 먼저 보여야 한다.

## 2. 구현해야 할 것 (우선순위순)

### [상] 레벨업 3택 화면
- 레벨업 시 게임을 잠시 멈추고 3장의 카드를 보여준다. 카드는 (신규 무기 / 주력 강화 / 패시브) 중 하나를 나타낸다.
- 카드마다 **무엇이 바뀌는지**를 한 줄로 쓴다. 현재 값에서 다음 값으로 가는 변화(예: 발사 수 2 → 3)가 보여야 선택 근거가 생긴다.
- 원소 약점 정보는 카드나 적 체력바 옆에 작게 붙인다. 판 안에서 별도 메뉴를 열게 하지 않는다.
- 터치 타깃은 최소 48dp 이상. 한 손 조작 환경이므로 카드가 엄지 도달 범위에 들어오게 배치한다.

### [상] 판 안 HUD
- 최소 항목: 체력, 현재 레벨과 경험치, 보스 진행 상황(예: 웨이브 2/3, 보스 체력). 남는 공간은 비운다.
- 감속 상태는 화면 가장자리 색 변화나 아이콘으로 명확히 보여준다. 감속 중인지 모르면 접근성 장치의 의미가 사라진다.
- 세이프 영역(노치, 홈 바)을 HUD 앵커에 반영한다.

### [상] 판 밖 성장 허브 (정보 구조)
- 성장축을 한 화면에 전부 펼치지 않는다. 탭 또는 목록으로 나누고, 각 축에 "현재 단계 / 다음 단계 / 필요 재화"만 보여준다.
- 축이 6개 이상이면 해금 순서와 안내(잠김 이유 표시)가 필수다. 잠긴 항목을 누르면 해금 조건을 말해 준다.
- 분석의 우려: 여러 재료와 축이 얽힌 복잡함. 재화 종류는 화면마다 2~3개로 제한한다(추정 기준).

### [중] 출격 전 확인 화면
- 출격 버튼 근처에 현재 장착 상태(파일럿, 기체)와 강화 요약을 보여 준다. 출격 전 점검 기회가 재도전 동기가 된다.

### [중] 일일 변형 규칙 표시
- 일일 도전 화면에 "오늘의 강화 1 + 부작용 1" 짝을 나란히 보여준다. 긍정과 부정을 같은 크기로 노출해야 선택이 명확해진다.

### [중] 방치 수익(순찰) 표시
- 적립 상한(예: 최대 시간)과 수령까지 남은 시간을 보여준다. 상한이 찼을 때 "더 쌓이지 않는다"는 사실을 표시한다. 숨기면 불만이 된다.

## 3. 하지 말 것
- 원작의 버튼 모양, 아이콘, 색 조합, 화면 레이아웃을 따라 하지 않는다.
- 유료 패키지 팝업을 판 종료 직후 자동으로 띄우지 않는다. 구매 유도는 사용자가 직접 여는 화면에만 둔다.
- 달성 불가 보상(분석 §2.7, §1.10의 카니발 사례)을 보상 화면에 전시하지 않는다. 표시하는 보상은 실제로 받을 수 있는 것만 둔다.

## 4. 열린 질문
- 판 안에서 HUD 정보를 얼마나 줄일지. 분석은 "가독성 우선"을 권했으나 밀도 기준은 미정이다.
- 확률 공개 화면(뽑기)의 필수 표기 범위. store-compliance-specialist 확인 후 확정한다.

## 5. 검증
- 3택 UI를 한 손 엄지 기준으로 실기기 확인(세로 화면, 노치 기기 포함).
- 해상도 2종 이상에서 카드 텍스트가 잘리지 않는지 확인(현지화 문자열 길이 대응).
- 성장 허브에서 잠긴 항목의 해금 조건 문구가 한 번에 이해되는지 5명 이상 확인.
